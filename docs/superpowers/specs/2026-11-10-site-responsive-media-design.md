# Site-wide responsive media design

## Проблема

Растровые изображения сайта подключаются неодинаково: часть статических изображений уже имеет AVIF/WebP, часть выводится обычным `img`, а Strapi feed часто возвращает одну ссылку. Размеры файлов не привязаны системно к реальным слотам верстки, `@2x` поддерживается не везде. В каталоге битые или отсутствующие изображения могут оставлять пустые либо некорректные области.

## Цель

Все растровые изображения сайта должны получать варианты, соответствующие фактическому размеру своего слота в верстке:

- `1x` и `2x`;
- AVIF, WebP и PNG;
- `<picture>` для контентных изображений;
- CSS `image-set()` для растровых фоновых изображений;
- явные `width` и `height` либо стабильное соотношение сторон для предотвращения layout shift.

SVG остаются исходными SVG и не проходят растровую конвертацию. Для SVG-слотов каталога и страницы товара используются отдельные серые SVG-placeholders соответствующего размера и aspect ratio.

Для каталога и страницы товара отсутствующее или поврежденное изображение заменяется серым placeholder. Допускается один комплект placeholder на каждый тип слота, размер и формат.

## Границы

В scope входят:

- все растровые изображения из корневого `public/`;
- растровые изображения из `strapi-catalog/public/uploads/`;
- React-компоненты, legacy runtime и HTML-шаблоны, которые выводят изображения;
- CSS-фоны с растровыми URL;
- карточки каталога, фильтры, hero-слайды и все изображения страницы товара;
- генерация и проверка responsive sidecar-файлов.

Не входят:

- изменение принятого дизайна, композиции, кропа или порядка секций;
- конвертация SVG в растровые форматы;
- placeholder за пределами каталога и страницы товара;
- изменение пользовательских CMS-данных, кроме необходимого медиаконтракта feed;
- цены и commerce-поведение.

## Выбранный подход

Используется централизованный build-time медиапайплайн.

1. Реестр типов слотов хранит целевой размер `1x`, размер `2x`, соотношение сторон и стратегию вписывания.
2. Генератор на Sharp создаёт детерминированные AVIF, WebP и PNG для обоих pixel density.
3. Manifest связывает исходный URL с доступными вариантами и их размерами.
4. Общий React-компонент и DOM/helper для legacy-кода формируют одинаковый `<picture>`-контракт: AVIF → WebP → PNG fallback, каждый с `1x` и `2x`.
5. Растровые CSS-фоны получают эквивалентный `image-set()`.
6. Catalog API не подменяет исходный URL единственным AVIF. Он передаёт или позволяет детерминированно получить полный responsive-набор.
7. Для каждого каталожного типа слота генерируется нейтральный серый placeholder с тем же размером и соотношением сторон. Ошибка загрузки заменяет весь набор источников, а не только `img.src`.
8. Для SVG-обложек товара используются отдельные desktop/mobile SVG-placeholders. Обложки Давоса не используются как fallback для других товаров.

## Типы слотов

Финальный реестр формируется по фактическим CSS-размерам и DOM-потребителям. Минимально он различает:

- карточку товара в каталоге;
- hero/слайдер каталога;
- основной слайдер страницы товара;
- полноэкранную галерею;
- изображения характеристик;
- изображения материалов;
- изображения справок фильтров;
- остальные уникальные растровые слоты маркетинговых страниц.

Одинаковые размеры и правила кропа могут использовать один тип. Разные aspect ratio или `object-fit` требуют разных типов.

## Правила генерации

- `1x` равен максимальному CSS-размеру слота в обычной раскладке, если `sizes` не задаёт меньшую адаптивную границу.
- `2x` имеет удвоенные ширину и высоту.
- Исходник не увеличивается сверх собственного разрешения без явного решения; отсутствие достаточного разрешения фиксируется проверкой как предупреждение или ошибка для критического слота.
- PNG fallback создаётся даже для JPG/JPEG-исходника, как потребовал заказчик.
- Генерация идемпотентна и обновляет sidecar, если исходник новее.
- Имена файлов стабильны и включают тип слота либо точные размеры, чтобы варианты разных слотов не конфликтовали.

## Placeholder

- Только каталог и страница товара.
- Нейтральная серая заливка без текста, логотипа и декоративных деталей.
- Комплект AVIF/WebP/PNG для `1x/2x` на каждый используемый тип каталожного слота.
- Отдельный серый SVG-placeholder на каждый SVG-тип слота и его соотношение сторон; как минимум отдельные desktop и mobile обложки страницы товара.
- Placeholder сохраняет размеры и aspect ratio целевого слота.
- Он применяется при пустом CMS-поле, 404, ошибке декодирования или отсутствии подходящего варианта.
- Ни одно отсутствующее медиа другого товара не заменяется изображением или SVG-обложкой Давоса.

## Совместимость и деградация

- Браузер без AVIF использует WebP; без WebP — PNG.
- SVG-обложки страницы товара продолжают работать как SVG; отсутствующая или поврежденная обложка заменяется серым SVG-placeholder.
- Видео не конвертируется этим пайплайном; его poster проходит общий растровый контракт.
- Если manifest временно недоступен, PNG fallback остаётся работоспособным.
- В `showcase` медиаконтракт не должен раскрывать commerce-поля и не меняет site-mode routing.

## Проверки и критерии успеха

1. Автоматический inventory не находит пользовательских растровых `<img>` без `<picture>` и `1x/2x` AVIF/WebP/PNG, кроме документированного allowlist.
2. Автоматический inventory не находит растровых CSS-фонов без `image-set()`, кроме документированного allowlist.
3. Для каждого зарегистрированного исходника существуют требуемые варианты с ожидаемыми pixel dimensions.
4. Для каждого растрового каталожного типа слота существует серый placeholder во всех шести вариантах: три формата × две плотности; для каждого SVG-типа слота существует соответствующий серый SVG-placeholder.
5. API и UI regression tests подтверждают responsive-наборы для карточки, hero, product slider, характеристик, материалов и video poster.
6. Тест поврежденного URL подтверждает замену на правильный placeholder без layout shift.
7. Проходят `typecheck`, релевантные unit/integration checks, `check:catalog-api`, `check:catalog-ui`, `check:catalog-perf`, `check:site-mode`, `check:showcase-server`, `check:showcase-ui` и `build`.
8. После изменений uploads локально выполняются `catalog:optimize-media`, `strapi:sync-seed` и `catalog:export-snapshot`.

## Рассмотренные альтернативы

- URL-конвенция без manifest отклонена: отсутствующие sidecar-файлы обнаруживаются слишком поздно и дают битые источники.
- Ручное добавление `<picture>` в каждом компоненте отклонено: правила размеров и fallback быстро расходятся.

## Принятые решения

- Scope: все растровые изображения сайта.
- Placeholder: только каталог и страница товара.
- Один placeholder-комплект допустим на каждый тип слота, размер и формат.
- SVG-слоты получают серые SVG-placeholders; fallback на изображения Давоса для других товаров запрещен.
- Реализация: централизованный генератор + manifest + общие render helpers.
