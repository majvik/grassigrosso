# Корректировка документов по обработке персональных данных

## Проблема

Текущий клиентский комплект в целом отражает ограниченный функционал сайта без личного кабинета, заказов и оплаты, но после повторной проверки выявлены юридически значимые уточнения: отдельное согласие должно быть доказуемым, фактический канал доставки через сервис обмена сообщениями нельзя описывать только как получателей чата, срок хранения должен учитывать достижение цели, а формальный запрос субъекта должен содержать обязательные реквизиты части 3 статьи 14 Федерального закона № 152-ФЗ.

## Объём текущей задачи

Изменяются только Markdown-источники клиентского комплекта, внутренний чек-лист и три итоговых DOCX. Код сайта, база данных, Метрика, Карты, API форм и доставка обращений в этой задаче не изменяются.

## Решение

1. Уточнить Политику: отдельность согласия, состав доказательств согласия, целевой и предельный сроки хранения, корректная категория провайдера сервиса обмена сообщениями, условия трансграничной передачи и обязательность актуального уведомления Роскомнадзора.
2. Уточнить согласие веб-форм: фиксируемые технические сведения, серверная дата и редакция согласия, получатели, срок и порядок отзыва.
3. Уточнить уведомление о cookie и внешних сервисах без изменения ранее согласованной модели предварительного выбора пользователя.
4. Дополнить бланк запроса субъекта обязательными реквизитами документа, сведениями о представителе, подтверждением связи с обработкой и правилом электронной подписи.
5. Сохранить отдельный бланк отзыва согласия и проверить его способ получения результата.
6. Пересобрать объединённый комплект и два отдельных бланка. Во всех DOCX использовать только Times New Roman и чёрный текст, кроме жёлтого выделения проверяемых реквизитов, названий операторов и домена. В нижнем колонтитуле справа должен быть только номер страницы.

## Границы

- Не добавлять документы для личного кабинета, регистрации, заказа, оплаты или отдельного вишлиста.
- Не называть Telegram Bot API. Использовать функционально точную категорию провайдера сервиса обмена сообщениями и уполномоченных получателей чата.
- Не утверждать, что технические меры уже реализованы. Их обязательность фиксируется во внутреннем чек-листе как условие публикации.
- Не менять исходный документ клиента в каталоге `source`.

## Критерии успеха

- Три DOCX пересобраны из актуальных Markdown-источников.
- В бланке запроса есть все реквизиты части 3 статьи 14 № 152-ФЗ.
- В текстах нет личного кабинета, регистрации, оформления заказа и онлайн-оплаты как действующих процессов.
- Получатели чата описаны вместе с провайдером сервиса обмена сообщениями.
- Все проверяемые реквизиты и `grassigrosso.com` выделены жёлтым во всех документах.
- В DOCX нет цветного текста, шрифт везде Times New Roman, буллеты не отображаются квадратами.
- На каждой странице справа внизу отображается только номер страницы.
- Все страницы всех DOCX отрендерены и визуально проверены.
